# Why Anthropic? — Design Engineer, Web (Creative Studio / Brand Web) — application answer
Target: 200-400 words. Status: working draft, refined from Rich's own dictated first pass per Anthropic's candidate AI guidance (draft yourself, Claude refines).

I really love this stuff, and I have for a long time. Fifteen years in production, longer if you count freelancing before that — but the real turning point was 2016, when React clicked for me, and Storybook landed in almost the same moment. A few years after that, Nx monorepos hit me as a second force multiplier: component-driven development, design systems, monorepo architecture, and code generation all started compounding together instead of living as separate concerns. Large-scale frontend architecture, the tooling around it, the whole React ecosystem — Storybook, Chromatic, Figma-to-code, design systems that manage themselves — this is the work I actually love building, not just a skill set I picked up.

What Anthropic represents to me is the next force multiplier in that same line. The things that took a dedicated team and months of plumbing — turning a Figma file into a typed, production-ready component, keeping a design system self-consistent as it scales — are becoming radically more accessible with AI in the loop, and I've already been building toward that: ForgeKit, my open-source CLI and MCP server suite bridging Figma to React to Storybook, has 5,700+ npm installs from real teams. I author MCP servers — the protocol you created — as part of my daily practice, not as a novelty.

That's the pull, honestly: this feels like an inflection point for frontend engineering specifically, the same way React-plus-Storybook and then Nx monorepos were inflection points for me personally. I want to be genuinely involved in it — not just using the tools Anthropic ships, but helping push forward how AI actually gets incorporated into design-and-engineering workflows, at the company positioned to champion that shift in a real way.
